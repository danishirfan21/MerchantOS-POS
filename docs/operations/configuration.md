# Configuration and permissions checklist

All paths below are operator-supplied. They are examples of interface requirements, not provisioned infrastructure or credentials.

| Consumer | Private configuration/mounts | Must not receive |
|---|---|---|
| POS/Admin | Existing TLS/DP/app DB secrets, protected ring; new random monitor-token file | Backup private key, storage-admin/writer secrets, operator DB connection, witness private key |
| Backup writer | Read-only pgpass for merchant_backup, public encryption cert, writer S3 JSON, local spool/state RW; encrypted DP XML RO if selected | Backup private key, witness key, DB write/superuser authority |
| Recovery operator | Separately approved private decryption key, pinned witness public cert and signed receipt, S3 reader JSON, fresh-target DB owner interface | Unrestricted public recovery API |
| Audit exporter | merchant_security_exporter DSN JSON, purpose-specific S3 writer JSON, optional minimumCheckpoint/witnessCertificate RO | Witness/backup private keys, raw business-table access, event payload mutation/delete permissions |
| Witness/verifier | S3 reader JSON, independent previous checkpoint and witness certificate; signing key only during checkpoint creation | App/DB credentials or backup private key |
| Monitor | Aggregate-only DB DSN, read-only status/public cert files, read-only storage check credentials, scope-only monitor token, receiver token, state RW | User sessions/passwords, MFA/recovery data, operator authorizations |

An audit export DSN file uses `{"dsn":"host=... dbname=... user=merchant_security_exporter password=..."}`. Optional `minimumCheckpoint` and `witnessCertificate` enforce continuity after restart/restore. The exporter processes a bounded 100 records per run; schedule at a capacity-tested interval and alert if oldest pending age exceeds two minutes. `systemd/merchantos-audit-export.*` provides a minimal template. More throughput does not authorize dropping events.

For a new independent checkpoint:

```sh
python deploy/operations/audit.py checkpoint --storage /custody/reader.json --head-key APPROVED_EXPORTED_KEY --head-hash APPROVED_SHA256 --checkpoint /custody/new-checkpoint.json --certificate /custody/witness.crt --private-key /custody/witness.key --previous /custody/last-trusted-checkpoint.json
```

For initial genesis only, omit `--previous` under separately approved setup. A new output path is mandatory. Keep the prior checkpoint/signature outside exporter administration. Verify with `audit.py verify --storage ... --checkpoint ... --certificate ... --status-file ...`; do not sign a replacement checkpoint just to silence a fork/integrity error.

Compose still binds only loopback HTTPS/redirect ports. New roles/password files are generated by isolated init and provisioned by migration administration. `operator_connection` is a separate identity-role connection and is mounted only for an explicitly gated CLI operation, along with just that operation's username/temporary credential/factor files. Normal app containers have read-only filesystems/capability drops and no private recovery mount. The backup role has pg_read_all_data; its credential is sensitive even though the encrypted payload is not plaintext.

Provider policies in `deploy/operations/policies/` are reviewed templates with purpose-prefix/bucket placeholders. Apply separate principals; deny deletion, conditional-write bypass and inappropriate retention changes. Independently test denied deletion/overwrite, exact-version retrieval, minimum/maximum retention and storage-administrator capabilities on the actual provider. S3-compatible behavior can differ. The local Moto TLS fixture is not an IAM/security certification of a provider.

No startup path invents a storage bucket, a paid account, a key custodian or an alert recipient. CI alone creates disposable fixture buckets and TLS receivers. All destructive drill entry points retain a CI-only/fresh-target guard.
