# Accessibility assessment scope

Target: relevant WCAG 2.2 A/AA criteria on supported retail workflows. This is an assessment, **not a compliance certification**. Sources: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing).

Axe-core 4.11.0 is lockfile-pinned in both browser suites. Reports use `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa`, retain violations and incomplete/manual-review items, and record screen/viewport. Admin serves the scanner only through a Playwright same-origin test route; production CSP is unchanged. Screens examined include POS catalog/Arabic/payment and Admin overview/products/inventory/orders. Authentication, MFA and forms retain their existing keyboard/focus and responsive tests. Never scan/capture active enrollment material for public evidence.

Keyboard scenarios cover F2 product search, payment entry, Shift-Tab wrap, Escape cancellation, restored trigger focus, drawer cancellation, stock review and validation focus. Dynamic cart totals/search result counts provide status semantics. A pending payment locks destructive edits and retains a clear uncertainty alert. Native labels and existing dialogs remain; no decorative ARIA replaces native controls. Reduced-motion preferences suppress POS motion. 320px reflow supplements required 390px mobile, 768px tablet and 1440px desktop.

Review final `accessibility.json`, screenshot assets and documented findings. Automated checks cannot establish reading order quality, meaningful announcement timing, all contrast over dynamic content, hardware touch behavior or complete WCAG conformance. No screen reader/browser combination was manually tested; NVDA/Firefox, JAWS/Chrome, VoiceOver/Safari and real assistive-technology user acceptance remain pending. Human keyboard/touch evaluation and actual printer output also remain unverified. Do not interpret zero serious automated findings as zero accessibility barriers.

Executed observations: POS run 41380882492 passed login plus catalog/Arabic/payment scans at all three viewports; Admin run 41379963932 passed Overview/Products/Inventory/Orders plus the blank MFA verification form at all three viewports. No tagged violations were reported on these sampled states; nonzero incomplete/manual-review items remain for some retail pages. Final source revisions and all results are retained in audited artifacts, rather than claiming entire-product WCAG compliance.
